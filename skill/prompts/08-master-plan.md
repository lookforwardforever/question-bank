# 题库总体规划与单元题量分配（Master Plan）

> 目标：全面覆盖机器人/具身智能知识体系，服务考试、面试与概念理解；不限题量，但每道题都要有真实来源（本地讲义或网络资料）。
> 原则：**广度优先、冷门也收、网络补新、目标数量驱动**。

## 一、出题颗粒度（每个单元内部怎么分）

| 知识对象 | 标配题量 | 题型组合 |
|---|---|---|
| 核心概念/算法（如 PPO、附加质量、流匹配） | 3 题 | 1 选择或判断 + 1 填空 + 1 简答 |
| 重点开源项目（如 RDT、SuperMimic） | 4 题 | 定位 1 + 架构/机制 2 + 对比或坑点 1 |
| 一般项目（391 份精读里的非重点） | 1–2 题 | 选择/判断为主 |
| 工程流程/系统设计（如 sim2real、部署链路） | 2–4 题 | 简答 + 论述 |
| 数学/公式手撕点 | 2 题 | 填空 + 简答 |
| 前沿新论文/新项目（本机没有的） | 2–4 题 | 来源必须是 arXiv/官网/GitHub URL |

难度统一按 **简单 3 : 中等 5 : 困难 2** 控制；每个单元至少 1 道论述题收尾，用来串全链路。

## 四、网络来源使用规则（本机文档之外的题）

1. 只在本机讲义没覆盖、或内容已过时才联网；本机已有且没过时的，优先用本机。
2. 网络来源限定：arXiv 论文页/PDF、项目官网、GitHub/Gitea 官方仓库、权威机构博客（NVIDIA/字节/智元等）、知名技术媒体。公众号文章只能当线索，事实要回 arXiv 或仓库核对。
3. `source` 直接填 URL；题干里涉及的数字（训练时长、参数量、频率）必须能在该 URL 找到，找不到就不写数字。
4. 网络题与本地题遵守同一套 Schema、同一套人话风格、同一套去重规则。
5. 发现本机讲义与权威来源冲突：以权威来源为准，并在 `explanation` 里注明“本机讲义为旧说法，新来源显示……”。
6. 构建器对 http(s) 来源只校验 URL 合法性，不联网探测，保证离线可构建。

## 五、生产节奏（解决“慢”的问题）

- 每批 **40 题**（一个 jsonl 片段一次写完），题型配比 16 选择 / 8 判断 / 8 填空 / 6 简答 / 2 论述。
- 目标数量驱动：片段题数不足就补写，直到 40 题再进构建，不允许“尝试几次就算了”。
- 每个单元连续 3–5 批做完再换单元，避免上下文反复跳转。
- 每批结束只跑一次 `build.cjs`，报错集中修，修完即提交。
- 网络调研每个单元开工前集中做 2–4 次搜索，把新项目清单一次备齐，不在出题中途反复搜。

## 六、完成判据

- 每个单元：核心概念覆盖率 100%（对照单元覆盖范围清单逐项打勾）、重点项目零遗漏、至少 1 道论述。
- 全库：无重复 topic、无失效本地来源、无非法 URL、难度比例接近 3:5:2。
- 网页端：每个领域筛选题量 ≥ 规划值的 90% 视为该单元收官。
